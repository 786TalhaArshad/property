# AGENTS.md

Real Estate ERP for Pakistan. Plain PHP + MySQLi, **no framework, no Composer, no npm, no build step, no tests**. Runs under XAMPP Apache/MySQL in the `property` subdirectory.

## Run / setup

- Serve from `http://localhost/property/`. `BASE_URL` is computed from `DOCUMENT_ROOT` in `includes/config.php`, so the app works in a subdirectory — always prefix absolute URLs/links with `<?= BASE_URL ?>`.
- Fresh install: open `install.php`, submit the DB form. It imports `database.sql` (schema + seed) and **regenerates `includes/config.php`** from a hardcoded template (DB creds: `localhost` / `root` / empty password / `property_erp`). `dummy_data.sql` is optional sample data, not loaded by the installer.
- Default login: `admin` / `admin123`.
- Lint with `C:\xampp\php\php.exe -l <file>` (php is not on PATH).

## Architecture

- File-per-page routing, no router. Root: `index.php` (dashboard), `login.php`, `logout.php`, `install.php`. Everything else lives in `pages/` (feature lists, `*_form.php` = add/edit, `*_view.php` = detail). `pages/reports/` holds 5 reports (`sales_report.php`, `rental_report.php`, `recovery_report.php`, `outstanding_report.php`, `income_expense_report.php`).
- **Active-project context**: the header has an "Active Project" dropdown (incl. "All Projects"). Selecting one stores `$_SESSION['active_project_id']` via `pages/switch_project.php?id=<id>&back=<url>` (`0` = All Projects). Most list/report pages default-filter to it and add/edit forms lock `project_id` to it — see Page conventions. Helpers in `functions.php`: `active_project_id()`, `active_project()`, `set_active_project()`.
- Shared code in `includes/`: `config.php`, `database.php` (opens global `$mysqli`), `functions.php` (helpers), `auth.php` (loads `$user` + perms), `header.php` / `sidebar.php` / `footer.php` (layout; footer pulls Bootstrap/jQuery/Chart.js from CDN).
- DB layer in `includes/functions.php`: `db_get($sql, $params)`, `db_all`, `db_exec` (returns last insert id). Params are bound automatically by PHP type (int→`i`, float→`d`, else→`s`) — match SQL accordingly. Use `%`-prefixing carefully: e.g. `next_number('PRP','properties','property_no')` generates `PRP-0001` style numbers when auto-numbering is needed. NOTE: `next_number()` strips the prefix plus ONE more char (the `-`), so numbers like `BK-0001` → next `BK-0002` (it scans `SUBSTRING(column, LENGTH(prefix)+2)`).
- Transfers & Withdrawals module: `pages/transfers.php` (list) + `pages/transfer_form.php` (form), gated by `accounting.view`/`accounting.manage`, records go in the `transfers` table. 5 types: `customer_to_customer`, `bank_to_cash`, `bank_to_bank`, `customer_withdraw`, `owner_withdraw`. Bank/cash movements (`bank_to_cash`, `bank_to_bank`, `owner_withdraw`) create a `journal` voucher; customer types do NOT. `customer_to_customer` credits `from_customer_id` and debits `to_customer_id` on their computed ledgers. `transfer_form.php?id=` edits a transfer (edit/delete blocked for `customer_withdraw`); editing a bank/cash transfer deletes the old linked voucher and re-posts a fresh one.
- Roznamcha (Day Book): `pages/roznamcha.php`, gated by `accounting.view`/`accounting.manage`, sidebar link under **Finance**. Rows come from posted `voucher_items` (one row per line), `receipts`, and `customer_to_customer` transfers, merged and sorted by date. Filters: project (`project_id`), bank (`bank_id`), and Start/End date. Cash vs bank is derived per row: voucher line code `1000` → Cash, code `1001-<bank id>` → that bank; receipts use `receipts.bank_id` (else Cash); transfers show `-`. Row actions: edit/delete voucher (→ `voucher_form.php`), delete receipt, edit/delete transfer.
- Vendors module: `pages/vendors.php` (list + modal add/edit/delete) + `pages/vendor_view.php` (profile + payments). Prefix `VEN` on `vendors.vendor_no`; vendor payments live in `vendor_payments` (FK to `vendors`, optional `bank_id` FK to `banks`). Gated by `vendors.view`/`vendors.manage`, sidebar link under **Parties** submenu.
- Rentals module: `pages/rental_agreements.php` (+ `rental_agreement_form.php`/`_view.php`), `tenants.php`/`tenant_view.php`, `rent_collections.php`, `owner_settlements.php`, gated by `rentals.view`/`rentals.manage`. Rent collections are **standalone `rent_collections` rows — they never create receipts or journal vouchers** (unlike sales receipts). `rent_schedule.paid_amount`/`status` (`pending`/`partial`/`paid`) are derived from the summed `rent_collections` for that schedule; `rent_collection_recalc_schedule()` in `rent_collections.php` re-derives them after add/edit/delete. Agreement statuses: `active`, `renewed`, `expired`, `terminated`, `vacated`.
- CRM module: `pages/leads.php` (+ `lead_view.php`), `call_logs.php`, `meetings.php`, `tasks.php`, gated by `crm.view`/`crm.manage`, sidebar link under **CRM**. Simple CRUD on `leads`/`lead_followups`/`call_logs`/`meetings`/`tasks` — no voucher/receipt coupling. Lead statuses include `new`, `contacted`, `qualified`, `proposal`, `follow_up`, `converted`, `lost`.
- Owners & Dealers: `pages/owners.php`/`owner_view.php`, `pages/dealers.php`/`dealer_view.php` under the **Parties** submenu (`owners.view`/`dealers.view`). Ledgers are **stored, not computed**: `owner_ledger` and `dealer_ledger` keep a running `balance` column (denormalized). `owner_settlements.php` (rentals module) inserts directly into `owner_ledger`; `dealer_payments` holds dealer payments. None of these create receipts or vouchers.
- Investors: `pages/investors.php`/`investor_view.php` under the **Parties** submenu (`investors.view`/`investors.manage`). Ledger stored in `investor_ledger` (same pattern as `owner_ledger` with running `balance`). COA `2070` Investor Payable (liability). When paying an investor via `cash_paid.php`: Dr Investor Payable `2070` / Cr Cash/Bank `1000`/`1001-<id>`, plus a debit row in `investor_ledger`. Prefix `INV`.
- Operations module: `pages/utilities.php` + `utility_view.php` (meter readings → `meter_readings`, bills → `utility_bills`) and `pages/maintenance.php` + `maintenance_view.php` (complaints, `technicians`, `maintenance_tasks`), gated by `utilities.view`/`.manage` and `maintenance.view`/`.manage`, sidebar link under **Operations**. Utility bills are marked `paid` manually — no vouchers/receipts are created.
- General Party module: `pages/general_parties.php` (list, balance = Payable − Paid − Receiving) + `pages/general_party_view.php` (stat cards + Add Entry + computed ledger). Entries in `general_party_entries` with `entry_type ENUM('payable','paid','receiving')`. Every entry posts a balanced `journal` voucher: payable = Debit selected account / Credit party COA `2000-<id>`; paid & receiving = Debit party COA / Credit Cash `1000` or bank `1001-<id>` (auto-created under parent `1000`/`1001`). Party prefix `GP`, entries `GPE`. Deleting an entry deletes its linked voucher. Helpers `general_party_account_id()`, `general_party_bank_account_id()`, `post_party_voucher()` live in `general_party_view.php`. Gated by `general_parties.view`/`.manage`, sidebar link under **Parties**.
- Employees module (salary ledger): `pages/employees.php` (list + modal add/edit/delete) + `pages/employee_view.php` (stat cards + Add Entry + computed ledger), gated by `employees.view`/`employees.manage` (slugs added to seed; new `2050` COA parent + `employees`/`employee_entries` tables). Entries in `employee_entries` with `entry_type ENUM('payable','paid')`, balance = Payable − Paid. Every entry posts a balanced `journal` voucher: payable = Debit selected expense account (default `5000` Salaries) / Credit employee COA `2050-<id>`; paid = Debit employee COA / Credit Cash `1000` or bank `1001-<id>`. `employee_account_id()` auto-creates parent `2050` (liability) if missing. Employee prefix `EMP`, entries `EMPE`. Deleting an entry deletes its linked voucher. Sidebar link under **Finance**. `employee_view.php`'s ledger **merges** `employee_entries` with **external** posted `voucher_items` against that employee's `2050-<id>` account (vouchers already linked to an `employee_entries.voucher_id` are excluded so entries made through the module aren't double-counted) — so a payroll voucher built in `voucher_form.php` (Dr `2050-<id>` / Cr bank) shows up in the employee ledger. Stat cards Payable/Paid/Balance are computed across the merged list.
- Contractors module: `pages/contractors.php` (list + modal add/edit/delete) + `pages/contractor_view.php` (stat cards + Add Entry + merged ledger), gated by `contractors.view`/`contractors.manage` (slugs 37/38 in seed; `contractors`/`contractor_entries` tables, COA `2060` Contractor Payable + `5600` Construction Expense). Same pattern as Employees: entries `entry_type ENUM('payable','paid')`, balance = Payable − Paid; every entry posts a balanced `journal` voucher — payable = Debit selected expense account (default `5600` Construction Expense) / Credit contractor COA `2060-<id>`; paid = Debit `2060-<id>` / Credit Cash `1000` or bank `1001-<id>`. Shared helper `contractor_payable_account_id()` in `functions.php` (mirrors `employee_payable_account_id()`, auto-creates parent `2060`). Contractor prefix `CON`, entries `CONE`. Deleting an entry deletes its linked voucher. Sidebar links under **Parties** submenu (Contractors) and **Ledgers** submenu (Contractor Ledger → `contractors.php`). Ledger merges external posted `voucher_items` against `2060-<id>` exactly like `employee_view.php` (excludes vouchers linked to `contractor_entries.voucher_id`). `cash_paid.php` supports party type `contractor` (default debit `'2060'`, inserts a `contractor_entries` `paid` row + voucher). A contractor can work on multiple projects: many-to-many table `contractor_projects` (contractor_id, project_id), managed on `contractor_view.php` via a **Projects** card (link/unlink dropdown, header badges linking to `projects.php?id=`). `contractor_entries` carries an optional `project_id` (FK SET NULL) — the Add Entry form and `cash_paid.php`'s contractor branch store it, the ledger shows a Project column, and a **Project-wise Summary** card totals Payable/Paid/Balance per linked project (plus a "No Project" row), including external posted vouchers split by `vouchers.project_id`. The ledger on `contractor_view.php` has a **project filter** (`?id=X&project_id=Y`) that filters ledger + stat cards to that project only (summary card stays global); its Print button opens `pages/contractor_ledger_print.php?contractor_id=X&project_id=Y` — a print-styled contractor ledger (company header + logo, running balance, Total Payable/Total Paid/Balance foot row, project filter shown).
- Cash Book: `pages/cashbook.php`, sidebar link under **Finance**, gated on `accounting.view`. A register of the Cash account (`1000`) with Cash In / Cash Out columns + running balance. Merges posted `voucher_items` on Cash, cash `receipts` (no voucher), and cash `rent_collections`. Filters: date range + project. Print: `pages/cashbook_print.php`.
- **Vouchers (3 Transaction Modes)**: All financial entries go through one of three voucher types:
  1. **Cash Received Voucher** (`cash_received.php`) — Receiving money from any party. Date auto-populated, select party from list, enter narration + amount, save. Impact: Cash/Bank account (`1000`/`1001-<id>`) debited, party account credited. Party's balance sits in Accounts Receivable (`1100`) if they owe us, or Accounts Payable (`2000`) if we owe them — managed via chart of accounts heads.
  2. **Cash Payment Voucher** (`cash_paid.php`) — Paying money to any party. Single search field finds parties (customer/vendor/owner/dealer/employee/contractor/investor) by name/CNIC/phone via AJAX across all types; selecting a party auto-detects type and shows outstanding balance. Debit account auto-determined: Customer→`1100` AR, Vendor→`2000` AP, Owner→`3000` Capital, Dealer→`2000` AP, Employee→`2050` Employee Payable, Contractor→`2060` Contractor Payable, Investor→`2070` Investor Payable. Separate "Pay Expense" button shows expense heads dropdown; "Pay Other" shows full COA dropdown.
  3. **Journal Voucher** (`voucher_form.php`) — Non-cash transfers, payroll, adjustments. Manual double-entry: select debit + credit accounts, amount, narration.
  Shared helpers in `includes/functions.php`: `coa_id_by_code()`, `cash_bank_account_id()`, `post_cash_voucher()`. Voucher prefixes: CR (cash receipt), BR (bank receipt), CP (cash payment), BP (bank payment). All post as `posted` status. Gated by `accounting.view`/`accounting.manage`, sidebar links under **Finance**.
- **Invoices**: Two types:
  1. **Sale Invoice** (`booking_form.php`) — Date auto, select Customer + Employee from list, property code shows property details, enter quantity, price, discount. On save: booking amount treated as advance → ledger update. Cash portion: Cash (`1000`) debited, Sales Income (`4000`) credited. Remaining installment amounts become Accounts Receivable (`1100`).
  2. **Purchase Invoice** (`purchases.php` + `purchase_form.php`) — Gated by `purchases.view`/`purchases.manage`, sidebar link under **Finance** (after Cash Book). List page with project/vendor/date filters; add/edit form with dynamic line items (Description, Qty, Unit Price). Vendor dropdown shows previous outstanding balance via AJAX. On save: totals + discount computed; journal voucher posted (Dr Purchases `5700`, Cr Accounts Payable `2000`); if `paid_amount > 0`, a separate payment voucher posted (Dr `2000`, Cr Cash `1000` or Bank `1001-<id>`). Status auto-derived (`pending`/`partial`/`paid`). Prefix `PUR`. `purchases.voucher_id` + `payment_voucher_id` link to the two vouchers; delete cascades to voucher_items + vouchers. Vendor profile (`vendor_view.php`) shows purchases tab with stat cards for Total Purchases / Purchase Amount / Total Paid / Contact.
- **Expense/Income Heads**: `pages/expense_heads.php` + `pages/income_heads.php` — head-wise managers over `chart_of_accounts` (`account_type` `'expense'`/`'income'`). Top-level heads have numeric codes; sub-heads get `<parent>-NN` codes. Modal add/edit, inline delete blocked when head has sub-heads or `voucher_items` rows. Ledger links pass `include_children=1` to `pages/ledger.php`. **Income = credit-normal, expense = debit-normal.** Gated by `accounting.view`/`accounting.manage`.
- **Financial Statements**: `pages/trial_balance.php`, `pages/profit_loss.php`, `pages/balance_sheet.php` in **Finance submenu** (`accounting.view`), distinct from the 5 reports in `pages/reports/`. COA-based (one row per account). All support project filter (default `active_project_id()`). Trial Balance + Balance Sheet have Start/End date filters. Balance Sheet appends computed net profit line.
- Print pages: `pages/vouchers_print.php` (all posted vouchers as a flat voucher-items register, respects `project_id`/`from`/`to`), `pages/ledgers_print.php` (each COA account's ledger with opening/closing + running balance; supports `account_id` for a single ledger, `account_type`, `project_id`/`from`/`to`, `include_children`), and `pages/customer_ledger_print.php` (single customer's computed ledger — bookings/transfers/payments, respects `project_id`/`property_id`/`start_date`/`end_date`, mirrors the `customer_view.php` Ledger tab). All three render a print header with company name + logo (`setting('company_logo')`, shown as `BASE_URL/assets/<path>`), a `@media print` stylesheet, and `page-break-before` per ledger section. Print buttons live in `vouchers.php` (toolbar), `ledger.php` (card-header "Print This Ledger"/"Print All Ledgers" + empty-state), and `customer_view.php` (Ledger tab filter bar).
- Sidebar (`includes/sidebar.php`) is grouped into accordion submenus (CRM, Real Estate, Parties, Sales, Rentals, Operations, Finance, **Ledgers** (separate top-level submenu with General Ledger, Expense/Income Ledger, Customer/Vendor/Dealer/Owner/Employee/General Party/Contractor/Investor/Tenant Ledger links), Reports, System (nested Master Data). Standalone top-level links: Documents, Notifications. `submenu_state($keys)` (in `functions.php`) accepts an array of `$active` keys and returns `active` to open+highlight the parent — use it on the parent link when a page lives inside a submenu. Collapse logic in `assets/js/main.js` closes sibling submenus so nested ones stay open.

## Page conventions (follow exactly)

- Every page begins: `require_once '../includes/auth.php'; require_login(); require_permission('<module>.view');` then set `$title` and `$active`, then `include '../includes/header.php';` and end with `include '../includes/footer.php';`. Exception: pages in `pages/reports/` are one level deeper — `require_once '../../includes/auth.php'`, gate on `reports.view`, set `$active = 'reports'` (that's the Reports submenu key).
- Permission slugs are `<module>.view` / `<module>.manage` (e.g. `properties.view`, `properties.manage`). Super admin bypasses all. Add new slugs to `database.sql` seed only if needed — the `permissions`/`role_permissions` tables are pre-seeded. **Exception — Master Data pages** (`countries.php`, `cities.php`, `areas.php`, `societies.php`, `payment_methods.php`, `banks.php`, `expense_categories.php`, `income_categories.php`, `document_types.php`, `branches.php`, property types/categories/amenities): they gate on `master.view` and gate add/edit/delete on `has_permission('settings.manage')` (not `<module>.manage`).
- POST handling pattern: `if (is_post()) { csrf_check(); ...; flash('success', '...'); redirect('relative_page.php'); }`. Every form must render `<?= csrf_field() ?>`.
- List/report pages default the project filter to the active project: `$project_id = (int)($_GET['project_id'] ?? active_project_id());` then add `AND <t>.project_id = ?` only when `$project_id > 0` (`0` = All Projects). Add/edit forms set `project_id` from the record when editing, else `active_project_id()`, and show the project field disabled/locked.
- Escape all output with `e()` (alias of `h`). Format with `fmt_money()`, `fmt_date()`, `status_badge()` (badge colors keyed off lowercase snake_case status strings).
- Every table carries `id, created_date, created_time, updated_date, updated_time` (DATE/TIME, not DATETIME). New inserts must set `created_date=CURDATE(), created_time=CURTIME(), updated_date=CURDATE(), updated_time=CURTIME()`; updates set `updated_date=CURDATE(), updated_time=CURTIME()`.
- Statuses are lowercase snake_case strings (e.g. `available`, `booked`, `pending`, `partial`, `paid`). Reuse existing values; if you add a new status, extend the map in `status_badge()`.

## Gotchas

- **Passwords are stored in plaintext** (`admin123` in `database.sql`; `login.php` checks via `hash_equals($row['password'], $password)`). Do not silently "upgrade" to `password_hash` — it requires coordinated changes to the seed data and login.
- `includes/config.php` is machine-generated by `install.php` from a template inside that file. Don't add logic there expecting it to survive a reinstall.
- `install.php` splits `database.sql` on `;` + newline, so SQL statements must each end with `;` followed by a newline. No triggers/procedures with internal semicolons.
- File uploads go through `upload_file()` into `assets/uploads/<subdir>/` and are stored as relative paths (`documents/2026..._xxx.png`), rendered as `BASE_URL/assets/<path>`. Upload dirs are created by `install.php`; `assets/uploads/` is untracked — don't commit uploaded files.
- Cascading dropdowns (blocks/roads/streets by project, areas/societies by city, etc.) are fetched via `pages/ajax.php?action=...&id=...`, which returns JSON. New dependent selects should reuse this file. Additional AJAX actions: `party_search` (search customers/vendors/owners/dealers/employees/contractors/investors by name/CNIC/phone across all types, param `q`; returns results with `type` field), `party_balance` (outstanding balance per party type, param `type`+`id`), `vendor_balance` (purchase outstanding, param `id`). `ajax.php` also handles POST `add_society`/`add_area` (gated by `settings.manage` + CSRF, JSON `{ok,id,name}`) — the quick-add "+" buttons in `projects.php` post there so new entries appear in the project modal's Society/Area dropdowns without a reload.
- Timezone is `Asia/Karachi`; currency comes from `setting('currency', 'Rs.')` (settings table).
- **`database.sql` only runs on a fresh install** (`install.php`). Schema changes to an already-installed DB must be applied to the live `property_erp` DB too — e.g. via `C:\xampp\mysql\bin\mysql.exe -u root property_erp` (PowerShell can't use `<`; pipe the file in). Keep both in sync (`transfers` table was added this way).
- Bank transfers auto-create chart-of-accounts sub-accounts `1001-<3-digit bank id>` under parent code `1001` (Bank Accounts). Dashboard bank balance aggregates codes `LIKE '1001%'`, so keep bank COA codes prefixed `1001`.
- **COA numeric scheme** (seeded in `database.sql`, `chart_of_accounts.code`): `1000` Cash, `1001` Bank Accounts, `1100` Accounts Receivable, `2000` Accounts Payable, `2050` Employee Payable, `2060` Contractor Payable, `2070` Investor Payable, `3000` Capital/Owner Equity, `4000` Sales Income, `4100` Rental Income, `5000+` expense heads (`5000` Salaries … `5700` Purchases). Sub-heads are `<parent>-NN`. Auto-created accounts: bank sub-accounts `1001-<bank id>` (under `1001`), party accounts `2000-<id>` (under `2000`, created by `general_party_bank_account_id()`/the party modules), employee accounts `2050-<id>` (under `2050`, created by `employee_account_id()`). When adding new heads keep codes within these parent ranges.
- Customer ledger (`pages/customer_view.php`) is computed, not stored: debit = non-cancelled bookings (`total_price - discount`), credit = receipts, plus `customer_to_customer` transfers. Cancelled bookings drop out automatically — that's how a booking withdraw adjusts the ledger. No per-customer AR accounts in the COA. **Receipts never create vouchers except the cash-sale booking receipt** (see sale types below). `pages/receipts.php` is a **read-only register** (list + project/date filters + print via `receipt_print.php`, no add/edit/delete); all receipts are created at the source — booking create (`booking_form.php`) or "Receive" on `booking_view.php`/`installments.php` (which update the linked installment's `paid_amount`/`status`).
- `pages/ledger.php` running balance is account-type-aware: income/liability/equity are credit-normal (`opening + credit − debit`), asset/expense are debit-normal. It also has `project_id` and Start/End date filters — the ledger opened from the heads pages passes `account_id`, optional `include_children=1`. **Everywhere that reads vouchers filters `v.status = 'posted'` — draft vouchers are invisible to all ledgers, reports, statements, and the roznamcha.** One exception: the dashboard's local `acct_balance($code)` in `index.php` sums `code LIKE '<code>%'` **without** the posted filter, so draft vouchers leak into the Dashboard Cash/Bank totals. Don't assume dashboard and reports agree, and don't "fix" one without the other.
- **Sale types on bookings** (`bookings.sale_type ENUM('cash','installment')`): **cash** = full payment now (`token_amount + booking_amount` must equal `total_price - discount`) → property `sold`, booking `completed`, no installment plan; payment mode comes from the Cash block (`payment_mode` `cash`/`bank`, `cash_bank_id`, `cash_reference`) and the auto-receipt is stored with that bank/reference. **On booking create (not edit), the upfront cash (token+booking) auto-creates a `receipts` row** linked to the paid `booking` installment — this keeps the customer ledger correct. Cash sales additionally post a balanced `journal` voucher (Debit Cash `1000` or the selected bank's COA `1001-<id>`, Credit Sales Income `4000`) via `post_booking_voucher()` / `booking_bank_account_id()` in `booking_form.php`, so the cash/bank balance and that bank's ledger show the sale. **installment** = token+booking paid now (Upfront Payment card fields `payment_method_id`/`bank_id`/`reference`, no voucher) → property `booked`; the remaining amount (`total − discount − book − possession − transfer`) is split into `installment_months` equal monthly installments (last one absorbs rounding; possession due `+installment_months` months). `installment_plan` is always `'monthly'`; `installment_months` (default 12) drives both the count and `installment_years = ceil(months/12)`.
- `tour_guide.php` (root) is a public, login-free user guide (Bootstrap CDN, no header/footer includes) linked from `login.php`.
- **`properties` has no `address` column** — the plot reference is `plot_no`. Detail pages alias it (`p.plot_no AS property_address`); writing `p.address` makes the whole page 500. Other property address-ish columns: `size_value`/`size_unit`.
- `includes/header.php` sets `$company = setting('company_name', APP_NAME)` (a string) on every page. Don't declare your own `$company` array before including the header — it gets silently overwritten (fatal "Cannot access offset on string" when read as array). Rename yours (e.g. `$companyInfo`).
- No git branching conventions beyond a single commit; commit only when asked.
